# Stage 1 provenance audit

Reviewed 2026-11-17 against the first local commit `313c53d` and the installed
qblox-scheduler 1.0.1 / qblox-instruments 1.4.1 distributions.

## Specific concern and comparison

The initial example was developed while reading
[Qblox Scheduler: Hello Quantum World](https://docs.qblox.com/en/main/quickstart/QBS_helloworld/qbloxscheduler_helloworld.html).
The page carries copyright 2026 Qblox BV. The linked official notebook ZIP was
inspected: it contains one notebook and no license file, license cell or license
metadata. A separate tutorial redistribution license was not established. That
uncertainty does not establish that every program calling the same API is a copy
of the tutorial. The earlier blanket publication hold conflated these questions.

| Exact project section (in `313c53d`) | Tutorial relationship | Classification and action |
| --- | --- | --- |
| `examples/dummy_cluster.py`, `build_schedule()` | Uses Schedule, ClockResource, SquarePulse and reference-relative timing, as in tutorial cells 1-2. | Retain ordinary API usage. The project specifies the requested two-pulse experiment (0.5/100 ns, 20 ns gap, 0.25/80 ns), rather than the tutorial's three-pulse experiment and later gate/acquisition extensions. No tutorial comments, docstrings or pulse/compiler implementation were copied. |
| `examples/dummy_cluster.py`, `main()` calls to HardwareAgent and compile | Same public entry points as tutorial cell 5. | Retain ordinary API calls. Explicit dummy enforcement, validation, registered-resource ownership, failure cleanup and exports were implemented for this project and do not occur in that tutorial example. |
| `config/dummy_hardware.json`, complete 19-line object | Same kind of QRM-RF/port mapping as tutorial cells 3-4. | Retain configuration data. Field names/type strings are library schema vocabulary. Slot 2, cluster0, q0:mw, q0.01 and 5 GHz were tutorial-informed lab choices, not mandatory identifiers; they are acknowledged as such. The single-output mapping contains no tutorial prose or algorithm. It is validated against the installed schema. |
| `docs/architecture.md`, explanation and Mermaid diagram | Describes concepts learned from linked official sources. | Retain original project explanations and diagram. No tutorial narrative or illustration is copied. |
| `docs/architecture.md`, annotated Q1ASM excerpt | Generated by running this project's experiment. | Retain generated compiler output and project-authored annotations; not a copied tutorial program. |
| Script export/configuration guards and all tests/workflow | Added to satisfy this project's functional and validation requirements. | Retain original implementation; no copied vendor implementation identified. |

The substantive similarities are public API use, the data schema and acknowledged
configuration choices. No tutorial-specific implementation, explanatory text,
notebook or image was identified as material needing removal. Consequently the
working Python and JSON are retained unchanged; no cosmetic rewrite or renamed
variables are presented as a provenance remedy. The inaccurate blanket hold in
README/notices was replaced by this specific audit. Earlier validation records
remain historical, and Git history is preserved.

## Verified package basis

The installed distribution license files were read in full and are reproduced in
[THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md): BSD-3-Clause for scheduler
1.0.1 and BSD-4-Clause for instruments 1.4.1. Both permit redistribution with
their stated notice/disclaimer requirements; the instruments acknowledgement
and non-endorsement statement remain in README.

The following installed scheduler sources were inspected to check the retained
API calls and configuration, including their BSD-3-Clause SPDX headers:

- `qblox_scheduler/schedule.py`: Schedule.add timing/reference arguments;
  copyright 2025 Qblox.
- `qblox_scheduler/operations/pulse_library.py`: SquarePulse parameters;
  copyright 2020-2025 Quantify Consortium and 2020 Qblox.
- `qblox_scheduler/qblox/hardware_agent.py`: dummy creation and compile entry
  points; copyright 2025 Qblox.
- `qblox_scheduler/backends/qblox_backend.py`: QbloxHardwareCompilationConfig;
  copyright 2020-2025 Quantify Consortium and 2021 Qblox.
- `qblox_scheduler/backends/types/qblox/`: hardware, module and options schemas.

Official source: [scheduler repository](https://gitlab.com/qblox/packages/software/qblox-scheduler).
Browsable source references:
[Schedule](https://docs.qblox.com/en/main/_modules/qblox_scheduler/schedule.html),
[HardwareAgent](https://docs.qblox.com/en/main/_modules/qblox_scheduler/qblox/hardware_agent.html).
Installed versioned sources, rather than rolling documentation, were used for
the concrete API checks. No source implementation was pasted into project files.

## Scope of the conclusion

There is no identified copied tutorial material left requiring an additional
redistribution permission for this repository's publication. This conclusion is
about the reviewed project content, not a claim that all Qblox documentation is
BSD-licensed. The original tutorial influence remains acknowledged. This was an
ordinary provenance review by an author already exposed to the tutorial, not a
formal clean-room process. Package copyright and full license notices remain
intact, and MIT applies only to original project contributions.
